1. 소프트웨어 및 제공 범위

OHT 통합 데이터 수집 플랫폼은 수동 수집, GELLO 상대 관절 추종, 키보드 인계, π0.5 DAgger, 궤적 재생, 궤적 증강, HEX 삽입 및 카메라 보정을 하나의 화면에서 제공합니다. 이 오프라인 버전은 2026년 11월 6일 .200에서 사용 중인 코드를 기준으로 제작했습니다.

포함된 모델은 T42 / 20,000 체크포인트 한 개입니다. 카메라 3대, 절대 joint 출력, chunk 30 설정이며 모델 구성, 정규화, tokenizer 및 추론 환경이 포함됩니다. 다른 모델과 과거 수집 영상은 제외됩니다.

인터넷 없이 화면과 로컬 추론을 사용할 수 있습니다. 다만 로봇 제어에는 PC, UR, OnRobot 사이의 로컬 네트워크가 필요합니다. 오프라인이라고 해서 로봇의 LAN 케이블을 분리하면 안 됩니다.

RL 화면 코드는 포함되어 있지만 외부 actor·learner, 학습 서비스와 인증 정보는 포함되지 않습니다. 이 패키지만 설치해도 RL 학습이 시작되지는 않습니다. 포함된 참조 궤적은 기존 지그용 예제이므로 새 작업장에서 다시 확인해야 합니다.

로봇 / 그리퍼원본 구성: UR16e, OnRobot 2FG14, HEX-E QC. UR Remote 모드와 기존 HEX 실행 코드에 호환되는 OnRobot URCap이 필요합니다. PC 패키지에 로봇 펌웨어와 URCap 설치는 포함되지 않습니다.
네트워크원본 주소: UR 192.168.8.100, OnRobot 192.168.8.101, PC .200. 새 PC 연결 시 IP 충돌을 피하세요. 인터넷은 필요하지 않습니다.
화면 / 권한그래픽 데스크톱과 Chrome/Chromium이 필요하며 조작 화면에 키보드 포커스를 두세요. 브라우저 사본, CJK 글꼴 및 USB 권한 설정 스크립트를 제공합니다. 시리얼 접근에는 dialout 그룹 권한이 필요합니다.

4. 오프라인 설치 및 시작

  1. tar.gz 3개와 tools, launchers, docs, inventory, udev를 포함한 전체 배포 디렉터리를 복사하세요. 압축 파일 하나만으로는 설치할 수 없습니다.
  2. 대상 PC의 NVIDIA 드라이버와 Ubuntu 데스크톱을 먼저 준비하세요. 설치 프로그램은 apt/pip/인터넷을 사용하지 않으며 원본 PC를 변경하지 않습니다.
  3. 다음 명령을 실행하세요. 두 번째 경로는 새 데이터 저장 위치로, 마운트된 SSD의 디렉터리를 지정할 수 있습니다. 기존 버전 덮어쓰기를 방지하기 위해 설치 대상 디렉터리는 없어야 합니다.
cd /path/to/OHT_OFFLINE_PACKAGE
bash install.sh "$HOME/OHT_offline" "$HOME/OHT_data"
bash "$HOME/OHT_offline/check_environment.sh"
bash "$HOME/OHT_offline/start_oht.sh"

http://127.0.0.1:8779에서 접속합니다. 로컬 모델 관리 포트는 8769입니다. 모델은 로드를 요청한 뒤 GPU에 올라가며, 화면 시작만으로 로봇이 움직이지 않습니다.

USB/시리얼 권한 문제가 있으면 대상 PC에서 아래 명령을 직접 실행한 후 로그아웃·로그인하고 장치를 다시 연결하세요.

sudo bash "$HOME/OHT_offline/tools/install_usb_rules.sh" "$USER"

카메라만 시작: bash ~/OHT_offline/start_cameras.sh. 로봇에 연결하지 않고 카메라만 시작합니다. RealSense Viewer를 동시에 열어 장치를 점유하지 마세요.

5. 최초 사용 및 이전 설정

실제 경로는 installation.json의 app, original, manager를 확인하세요. 원본 하드웨어 설정은 새 장치의 자동 보정 결과가 아닙니다.

  1. app과 original의 cameras.json에서 시리얼 번호를 확인하세요. camera_0 / camera_1 / camera_2는 CAM 01 / 02 / 03에 대응합니다. USB 인식 순서만 보고 모델 입력 순서를 바꾸지 마세요.
  2. 같은 로봇을 사용할 경우 LAN 주소를 유지하세요. 주소를 변경한다면 웹 화면뿐 아니라 제어, 경로 확인, HEX 통신 설정을 함께 수정해야 합니다. 원본 UR=.100, OnRobot=.101입니다.
  3. GELLO의 /dev/serial/by-id, 관절 영점 및 teleop/calibrations의 그리퍼 보정을 확인하세요. 현재 J6 설치 보정은 +90°이며 다른 GELLO에도 맞는다는 보장은 없습니다.
  4. 원본 툴 기준: TCP Z=232 mm, payload=2.5 kg, CoG=(-9, 6, 76) mm. 실제 툴이 같을 때만 재사용하세요. PC 프로그램 복사는 티치 펜던트 Installation을 바꾸지 않습니다.
  5. 그리퍼 목표 폭은 5–55 mm이며 닫힌 실측 끝점은 약 4.5 mm입니다. 물체를 잡으면 빈 그리퍼의 끝점에 도달하기 전에 멈출 수 있습니다.
  6. 새 장치에서는 예전 경로 확인 캐시를 재사용하지 마세요. examples/source_machine의 보정과 윤곽은 예제입니다. 장착 위치가 달라지면 다시 보정하거나 추출하세요.

우측 상단에서 English / 中文 / 한국어를 선택합니다. 최초 기본 언어는 영어입니다. 언어 전환은 기존 데이터나 사용자가 입력한 작업 문장을 바꾸지 않습니다.

6. 수동 전체 작업 수집

  1. 수동 · 전체 작업을 선택하고 작업 지시문과 최대 시간을 설정하세요. 기본 문장은 “Grasp the wheel and fit it onto the shaft.”입니다.
  2. 세 카메라 미리보기를 확인하세요. 장치 검사는 필요할 때 사용합니다. GELLO 정렬은 실제 관절 이동이므로 툴, 로봇 팔, 케이블 경로를 확보하세요. 절대 정렬 대신 현재 UR/GELLO 자세를 기준으로 상대 관절 추종을 시작할 수도 있습니다.
  3. 준비 과정은 정식 데이터에 포함되지 않습니다. 준비가 끝나면 수집 시작을 누릅니다. 상주 카메라는 다음 회차에도 재사용합니다.
  4. 키보드, GELLO, HEX 또는 참조 궤적 보조로 전환할 수 있습니다. 보조는 선택한 참조의 진행 상태와 그리퍼 단계를 고려합니다. 삽입 위치에 접근하기 전에 지그와 참조가 일치하는지 확인하세요.
  5. 성공/실패로 종료한 후 데이터를 보관하거나 삭제합니다. 백그라운드 저장 중에도 화면이 허용하면 다음 회차를 진행할 수 있습니다. 저장 중에는 데이터 디스크를 분리하거나 전원을 끄지 마세요.

그리퍼는 연속 폭 추종 또는 쥐기 전환 모드를 선택할 수 있고 독립 열기/닫기 버튼도 사용할 수 있습니다. 정렬 후 실제 개방 폭을 확인하세요.

이동 키를 길게 누르면 연속 이동하고 놓으면 감속 후 정지합니다. 명목 속도는 40 mm/s, 위치 목표 선행 한도는 4 mm입니다. 4 mm는 실측 위치보다 앞선 목표의 한도이며, 클릭당 정확히 4 mm 이동한다는 뜻은 아닙니다.

페달 바인딩은 브라우저에 로컬 저장됩니다. 새 PC/웹 주소에서 다시 바인딩하세요. 키보드 인계, GELLO, 궤적 보조 등을 지정할 수 있습니다. 사용자 바인딩이 우선합니다. 입력칸 밖의 빈 화면을 클릭한 후 단축키를 사용하세요. F8이 운영체제에 잡힐 수 있으므로 HEX는 숫자 3을 권장합니다.

화면 STOP은 PC 수집 절차를 종료합니다. 제어기의 안전 정지와 하드웨어 비상 정지는 별개입니다. 브라우저 단축키를 비상 정지로 간주하지 마세요.

8. DAgger 및 T42 Policy

다른 체크포인트 로드: 모델 목록 옆의 “체크포인트 폴더 선택”을 누르세요. OHT 컴퓨터나 마운트된 드라이브를 탐색하거나 경로를 입력합니다. COMMITTED.json, params/, assets/가 포함된 폴더(보통 20000) 또는 그 안의 params 폴더를 선택하세요. 설정을 자동으로 인식하면 “선택 후 로드 / 워밍업”을 누릅니다. 등록은 새로고침 후에도 유지됩니다. 파일을 업로드하거나 복사하지 않으므로 선택한 경로를 계속 사용할 수 있어야 합니다. 학습 설정, 정규화 및 커밋 정보가 없는 임의의 가중치 폴더는 바로 로드할 수 없습니다.

  1. DAgger와 T42 / 20,000을 선택하세요. 실제 존재하며 여유 메모리가 있는 GPU를 선택합니다. 단일 GPU PC는 GPU 0을 사용하세요.
  2. 일반 비동기 Policy 또는 RTC를 선택하고 로드/예열 후 READY를 기다리세요. 첫 실행에는 컴파일이 필요합니다. 기존 PC 전용 컴파일 캐시는 제외되어 처음 시작이 더 느릴 수 있습니다.
  3. 필요하면 장치 정렬 · 학습 궤적 시작점을 사용하세요. 실제 로봇 이동이 발생합니다. 개방 루프 검증은 저장된 학습 관측을 사용하므로 실시간 영상 기반 폐루프 실행과 다릅니다.
  4. 수집 시작을 누르면 Policy가 실행됩니다. 수정이 필요하면 1로 키보드, 2로 GELLO, 3으로 HEX 또는 궤적 보조를 사용합니다. 7로 Policy에 복귀합니다. 화면의 활성 상태를 확인하세요.
  5. 전체 회차를 저장하고 제어 출처별로 구간을 표시합니다. 모델 출력은 자동으로 전문가 라벨이 되지 않으며 학습 시 사람의 수정 구간을 선택할 수 있습니다.

회차 종료는 상주 모델을 언로드하지 않습니다. 브라우저를 닫아도 모델 프로세스는 종료되지 않습니다. PC 재시작 후 다시 로드하세요. 수집 중 모델 교체나 강제 프로세스 종료를 피하세요.

접촉 보호에는 유효한 힘 입력, 영점 및 실행 상태가 필요합니다. 소프트웨어 감속은 UR 충돌 보호를 대체하지 않습니다. 이전 후 툴과 힘 신호를 다시 확인하세요.

9. 재생, 필터링 및 궤적 증강

  1. 궤적 라이브러리에서 성공 궤적을 선택하세요. 필터링은 정지·미세 동작과 전환 구간을 검사하여 참조 복사본을 생성하며 원본 RGB/깊이는 바꾸지 않습니다. 속도 배율은 명목 참조 시간을 바꾸지만 실제 시간은 추종, 그리퍼 대기, 제어 한도에 영향을 받습니다.
  2. 궤적 증강에서 참조를 선택하고 이 참조 사용을 누른 후 백그라운드 준비를 기다리세요. 전체 재생이 여기에 통합되어 이전의 별도 Replay 화면은 필요하지 않습니다.
  3. 참조 시작점으로 정렬한 다음 참조 검증을 실행하세요. 최초 정렬과 중간의 가까운 후속 지점 찾기는 다릅니다. 중간 재개 시 작업 진행과 그리퍼 단계를 유지해야 합니다.
  4. 참조 검증 후 자동 증강을 실행하세요. 시간 증강은 리듬을, 공간 증강은 실제 경로를 변경합니다. 편차 곡선으로 각 단계와 현재 진행을 확인하세요.
  5. 매 회차 결과를 확인하고 공작물을 복원한 뒤 다음 회차를 시작하세요. 참조를 바꾸면 새 후보가 생성됩니다. 한 번의 성공이나 옛 캐시가 모든 새 경로를 검증하지는 않습니다.

원본 지그에서는 일부 자유 공간 단계의 최대 20 mm 편차, 접촉 전 소규모 편차 및 접촉 후 시간 변화만 확인했습니다. 이는 원본 현장 조건이며 새 설치의 기본 안전 여유가 아닙니다. 단계별 여유 공간과 접촉 위치를 다시 확인하세요.

10. 카메라, 영상 향상 및 보정

  • 세 카메라 모두 RGB와 깊이를 저장합니다. 미리보기의 좌우/상하 반전, 회전, CLAHE, 밝기 및 대비는 표시만 바꾸며 학습용 원본 영상은 유지합니다. 화면 방향과 모델 입력 매핑은 별개입니다.
  • 상주 프로세스는 카메라를 한 번 열고 정식 수집 기간에만 데이터를 저장합니다. USB 오류 복구 전 현재 회차를 종료하고 같은 장치를 여러 프로그램에서 동시에 열지 마세요.
  • 보정: 새 배치 → RGB 내부 파라미터 샘플 수집 → 내부 파라미터 계산 → 필요한 카메라 외부 파라미터 계산 → 투영 검증 순서입니다. 한 그룹만 풀어도 해당 카메라 투영을 검증할 수 있습니다.
  • 결과에 행렬이 표시됩니다. 필요하면 수집 데이터에 보정값 저장을 켜세요. 회차별 스냅샷을 저장하여 나중에 다시 보정해도 과거 기록을 덮어쓰지 않습니다.
  • 참조 윤곽: 성공 궤적의 그리퍼가 닫히기 직전 후보 프레임을 찾고 휠·그리퍼 영역을 확인한 다음 추출·저장합니다. 새로고침 후 다시 사용할 수 있으며 카메라 위치가 바뀌면 새로 생성하세요.

기존 중국어 보정 설명서도 소스에 포함되어 있습니다. 원본 PC 보정 예제는 자동 활성화되지 않습니다. 역할, 시리얼 번호, 해상도 및 장착 자세를 확인하세요.

11. 결과 저장 및 데이터 위치

예제 설치 명령의 새 데이터는 ~/OHT_data/unified/episodes/<UTC-ID>/에 저장됩니다. 다른 저장 경로를 지정했다면 installation.json과 화면의 경로를 확인하세요.

내용설명
annotation.json성공/실패, 보관 선택, 메모 및 시작/끝 삭제 필요 표시. 표시만으로 영상을 자르지는 않습니다.
metadata.json / collection_summary.json / quality.json작업, 구성, 완료 및 자동 품질 보고서. 작업 성공과 데이터 품질 통과는 다른 판단입니다.
index.jsonl카메라·UR·그리퍼·힘의 동기화 인덱스. 정확한 필드는 schema를 확인하세요.
camera/세 카메라의 RGB, 깊이, 타임스탬프 및 SDK 보정. RealSense 깊이 배율은 calibration.json에 있고 ZED는 uint16 밀리미터 깊이를 사용합니다.
teleop/실측/목표 상태, 이벤트, 종료 진단. HEX 손목 힘/토크와 그리퍼 피드백은 별도 신호입니다.
dagger_*/replay_*/augmentation_*사용 모드에 따른 제어 출처, 재생 진행, 증강 구간 라벨.
camera_calibration/활성화되고 유효한 경우의 내·외부 파라미터 스냅샷.

데이터 삭제는 해당 회차의 원본을 삭제합니다. 보관은 백그라운드 저장이 끝날 때까지 데이터를 유지합니다. 실제 작업 성공이 영상과 시간 정보의 완전성을 보장하지는 않으므로 품질 오류를 확인하세요.

12. 문제 해결

증상조치
화면이 안 열림 / 버튼 비활성로컬 8779/8769 포트와 ui_runtime/offline_server.log를 확인하세요. 이전 회차 결과와 현재 단계를 처리하세요. 상태 검사를 우회하지 마세요.
다른 앱에서는 카메라가 열림장치를 점유하는 앱을 닫고 시리얼, USB 3 실제 속도 및 끊김 로그를 확인하세요. 브라우저 새로고침으로 물리적 USB 문제는 해결되지 않습니다.
RealSense 프레임 없음 / 줄무늬수집을 중지하고 짧은 직결 케이블로 한 대씩 비교하세요. 불안정한 연장선이나 USB 2 대역폭 공유를 피하고 필요하면 컨트롤러·전원을 확인하세요.

Policy 로드 실패T42 단일 등록, 20,000 메타데이터, 전체 가중치, GPU 메모리, tokenizer 및 runtime을 확인하세요. 다른 모델을 임의로 다운로드하지 마세요.

수집 디렉터리 준비 안 됨저장 경로와 디스크 마운트를 확인하세요. 오류를 감추기 위해 끊어진 링크를 시스템 디스크로 바꾸지 마세요.

13. 백업, 업데이트 및 검증 범위

  • 배포 디렉터리와 SHA256SUMS를 보관하세요. 설치 프로그램은 기존 경로 덮어쓰기를 거부합니다. 새 버전은 새 경로에 설치하고 이전 버전을 복구용으로 유지하세요.
  • 코드 변경 전 수집과 결과 선택을 마치고 구성, 참조, 보정, 데이터를 백업하세요. 기존 PID, 잠금, 인증 토큰 및 경로 유효성 캐시는 옮기지 마세요.
  • 데이터는 별도 저장됩니다. 인덱스, 메타데이터, 주석, 힘/로봇 로그와 camera 전체 트리를 함께 보존하세요. 영상만으로는 전체 데이터 백업이 되지 않습니다.
  • 패키지 검사는 파일 무결성, 경로 이전, 라이브러리 import 및 오프라인 화면에 대한 것입니다. 대상 PC의 실제 카메라 수집, GPU 예열, UR 실제 운동은 검증하지 않았습니다. 환경 검사 실패를 먼저 해결하세요.
  • 소스와 모델 설정을 유지하며 타사 라이선스도 원래 구성요소와 함께 보존합니다. 제조사 SDK/드라이버에는 해당 라이선스가 적용됩니다.

범위는 package.json, 실제 검증은 verification.json에서 확인하세요.
