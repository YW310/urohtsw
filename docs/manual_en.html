1. Software and scope

OHT combines manual collection, relative GELLO joint following, keyboard takeover, π0.5 DAgger, reference replay, trajectory augmentation, HEX insertion and camera calibration in one console. This offline edition snapshots the deployed .200 software on 6 November 2026.

The only policy checkpoint included is T42 / 20,000 updates: three cameras, absolute joint actions, chunk size 30. Configuration, normalization, tokenizer and inference runtime are included. Other checkpoints and historical recorded videos are excluded.

The UI and local inference can run without Internet access. Robot operation still needs a local network connecting the workstation, UR and OnRobot. Offline does not mean disconnecting the robot Ethernet cable.

The RL UI code remains, but the external RL actor, learner, training services and credentials are not included. This package alone does not start RL training. Included references describe the source fixture and require validation at the new site.

4. Offline installation and launch

  1. Copy the entire delivery directory, including all three tar.gz files, tools, launchers, docs, inventory and udev. A single archive is not sufficient.
  2. Prepare the NVIDIA driver and Ubuntu desktop first. The installer uses no apt/pip/network and does not alter the source workstation.
  3. Run these commands. The second path selects new recording storage and may point to a mounted SSD. The installation directory must not already exist, preventing accidental overwrite.
cd /path/to/OHT_OFFLINE_PACKAGE
bash install.sh "$HOME/OHT_offline" "$HOME/OHT_data"
bash "$HOME/OHT_offline/check_environment.sh"
bash "$HOME/OHT_offline/start_oht.sh"

Open http://127.0.0.1:8779. The local model manager uses port 8769. GPU weights load only when requested; starting the UI does not move the robot.

For USB/serial permission errors, explicitly run on the target machine, log out/in, then reconnect devices:

sudo bash "$HOME/OHT_offline/tools/install_usb_rules.sh" "$USER"

Cameras only: bash ~/OHT_offline/start_cameras.sh. This starts cameras without a robot connection. Do not concurrently open another RealSense Viewer.

5. First use and migration settings

Use the app, original and manager paths in installation.json. Source hardware settings are not automatic calibration of a new machine.

  1. Check serial numbers in cameras.json under both app and original. Preserve camera_0 / camera_1 / camera_2 mapping to CAM 01 / 02 / 03. Never reorder model images based on USB enumeration.
  2. Keep the robot LAN addresses when using the same hardware. If changing IPs, update control, read-only path checks and HEX communication together, not only the web page. Source UR=.100, OnRobot=.101.
  3. Check GELLO /dev/serial/by-id, joint zero offsets and gripper calibration in teleop/calibrations. The current J6 mounting correction is +90°; do not assume it applies to another GELLO.
  4. Expected source tool: TCP Z=232 mm, payload=2.5 kg, CoG=(-9, 6, 76) mm. Reuse only for the same actual tool. Copying software does not change the pendant Installation.
  5. Gripper command range is 5–55 mm; the measured closed endpoint is approximately 4.5 mm. Contact with an object can stop closure above the empty endpoint.
  6. Do not reuse old path-check caches on a new machine. Calibration and contours in examples/source_machine are examples; recalibrate/recreate if mounts changed.

The top-right selector supports English / 中文 / 한국어, defaulting to English. Switching UI language does not rewrite historical data or a user-entered task.

6. Manual full-task collection

  1. Select Manual · Full task. Set the instruction and duration. The default task is “Grasp the wheel and fit it onto the shaft.”.
  2. Inspect all previews. Device checking is optional. GELLO alignment physically moves robot joints: clear the complete tool, arm and cable route. Alternatively, start relative joint following from current robot/GELLO anchors without absolute alignment.
  3. Preparation is not the recorded episode. Press Start collection when ready. Resident cameras remain available between rounds.
  4. Switch among keyboard, GELLO, HEX and reference assistance. Assistance uses the selected reference with progress/gripper-stage constraints; verify the fixture before approaching insertion.
  5. End with success/failure, then keep or delete the episode. Background saves may continue while the UI permits another round. Do not unplug recording storage or power off while saving.

Choose continuous gripper-width following or squeeze-to-toggle mode. Independent open/close controls are also available. Confirm the actual opening after alignment.

Hold translation keys for continuous movement; release to decelerate to a stop. Nominal jog speed is 40 mm/s with a 4 mm position lead. The 4 mm value bounds the target ahead of feedback; it is not an exact displacement per click.

Pedal bindings are stored locally in the browser. Rebind on a new computer/origin; options include keyboard takeover, GELLO and trajectory assistance. Custom bindings take precedence. Click the console outside input fields before using shortcuts. F8 may be captured by the desktop; prefer digit 3 for HEX.

UI STOP ends the PC collection flow. Controller safety stops and hardware emergency stop remain separate. A browser shortcut is not a hardware emergency stop.

8. DAgger and the T42 policy

Load another checkpoint: Click “Select checkpoint folder” beside the model list. Browse this OHT computer or a mounted drive, or enter a path. Select the directory containing COMMITTED.json, params/ and assets/ (usually 20000), or its params subfolder. The configuration is detected automatically. Click “Select and load / warm up”. Registration persists after refresh. Files are not uploaded or copied; keep the selected location available. An arbitrary weights folder without training configuration, normalization and commit metadata cannot be loaded directly.

  1. Choose DAgger and T42 / 20,000. Select a GPU that exists and has free memory; use GPU 0 on a single-GPU machine.
  2. Choose normal asynchronous Policy or RTC, then load/warm up and wait for READY. The first run compiles code; old machine-specific compilation caches are excluded, so first startup may be slower.
  3. Use Align device · Training trajectory start when needed. This causes physical motion. Open-loop validation uses saved training observations and is not closed-loop live-vision execution.
  4. Start collection runs the Policy. When correction is needed, use 1 for keyboard, 2 for GELLO, 3 for HEX, or trajectory assistance. Use 7 to return to Policy. Follow the enabled state shown on screen.
  5. The entire episode is retained and segmented by control source. Model predictions are not automatically expert labels; training can select human correction segments.

Ending an episode does not unload the resident model. Closing a browser does not end the model process. Reload after reboot; do not replace models or kill processes during collection.

Contact protection depends on valid force inputs, zeroing and runtime state. Software slowdown does not replace UR collision protection. Verify the tool and force signal again after migration.

9. Replay, filtering and augmentation

  1. Select a successful trajectory in the library. Filtering generates a reference copy, leaving original RGB/depth unchanged; it checks static motion, small actions and transitions. Speed factors change nominal reference time; execution can still be limited by tracking, gripper waits and control limits.
  2. Open Trajectory augmentation, select a reference and choose Use this reference. Wait for background preparation. Full replay is integrated here; the older separate Replay page is no longer needed.
  3. Align to the reference start, then validate the reference. Initial alignment differs from finding a nearby forward continuation point; continuation must retain task progress and gripper phase.
  4. Run automatic augmentation only after reference validation. Timing variation changes pace; spatial variation changes the actual path. Use the deviation curve to inspect stages and current progress.
  5. After each trial, confirm the result and reset the workpiece before the next. A new reference generates new candidates; one success or an old cache does not validate all new paths.

The source fixture had confirmed free-space offsets up to 20 mm in some phases, smaller pre-contact offsets and timing-only changes after contact. These are source-site conditions, not universal clearance values. Recheck phase clearance and contact locations at a new installation.

10. Cameras, enhancement and calibration

  • All three cameras save RGB and depth. Preview mirroring, rotation, CLAHE, brightness and contrast affect display only; training images remain raw. Display orientation is separate from model camera mapping.
  • Resident camera processes open devices once; persistent episode recording starts only during collection. Stop the round before fixing USB faults. Avoid multiple owners of the same camera.
  • Calibration: create a batch → collect RGB intrinsic samples → solve intrinsics → solve required extrinsics → validate projection. One solved extrinsic group is enough to validate that camera; all three are not required.
  • Solved matrices are displayed. Enable saving calibration to episodes when needed; each episode receives a snapshot so later recalibration does not rewrite old records.
  • Reference contour: find a frame just before closure in a successful trajectory, confirm wheel/gripper regions, extract and save the contour. Saved contours can reload after refresh; recreate after moving a camera.

A legacy Chinese calibration guide is also retained with the source. Source-machine calibration examples are not activated automatically. Confirm roles, serial numbers, resolution and mounts before using them.

11. Results and data locations

With the example install command, new data lives at ~/OHT_data/unified/episodes/<UTC-ID>/. For custom storage, follow installation.json and the displayed path.

ContentMeaning

index.jsonlSynchronized camera/UR/gripper/force references; inspect schema for exact fields.
camera/RGB, depth, timestamps and SDK calibration for three cameras. RealSense depth scaling is in calibration.json; ZED depth uses uint16 millimeters.
teleop/Measured/commanded state, events and stop diagnostics. HEX wrist wrench and gripper feedback are distinct signals.
dagger_*/replay_*/augmentation_*Control-source, replay-progress and augmentation labels as applicable.
camera_calibration/Intrinsic/extrinsic snapshots when enabled and available.

Delete data removes that episode’s originals. Keep data retains it while background saving finishes. A successful physical task does not prove that images and timestamps are complete; inspect quality errors.

13. Backup, updates and validation scope

  • Keep the delivery directory and SHA256SUMS. The installer refuses existing destinations; install updates into a new directory and retain the old copy for rollback.
  • Finish collection and result selection before changing code. Back up configuration, references, calibration and data. Never migrate old PIDs, locks, tokens or path-validity caches.
  • Recordings are separate. Preserve indexes, metadata, annotations, force/robot logs and the entire camera tree; videos alone are not a full dataset backup.
  • Package checks cover file integrity, relocation, library imports and offline pages. Target-machine camera capture, GPU warmup and UR motion are not verified; resolve failed environment checks first.
  • Source and model configuration are retained. Third-party licenses remain with their components; vendor SDKs/drivers retain their own licensing terms.

See package.json for scope and verification.json for actual validation.
