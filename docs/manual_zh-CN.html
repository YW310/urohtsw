1. 软件与交付范围

OHT 统一数据采集平台把手动采集、GELLO 相对关节跟随、键盘接管、π0.5 DAgger、轨迹回放、多样性扩充、HEX 搜孔和相机校准放在同一操作台。此离线版基于 2026-11-06 的 .200 现用版本制作。

模型仅包含 T42 / 20,000 checkpoint：三相机、绝对 joint、chunk 30。包含模型配置、归一化、tokenizer 和推理环境。不会将其他模型或历史采集视频混入安装包。

没有互联网也可以使用本地界面和本机推理。但机器人控制仍需要电脑与 UR、OnRobot 之间的局域网连接；“离线”并不意味着拔掉机器人网线。

RL 界面代码保留，但外部 RL actor／learner、在线训练服务和其令牌不在此包内。仅安装本包不会启动 RL 训练。已保存的参考轨迹是旧工装的示例，需要在新现场重新确认。

2. 安装要求与源机配置

项目要求 / 基准
操作系统基准：Ubuntu 20.04.6 LTS、Linux x86_64。不是 Windows 或 ARM 安装包；其他 Ubuntu 版本尚未验证。
GPU / 驱动源机：2× RTX A5000，每卡 24 GB；NVIDIA 535.183.01。ZED 深度和本机 Policy 需要可用的 NVIDIA GPU。24 GB 是源机配置，不是对所有显卡的最低显存保证；以目标机预热结果为准。
CUDA / Python已带 ZED SDK 4.2.5、CUDA 11.8 用户态运行库；采集 Python 3.11、ZED Python 3.8、模型独立运行环境。显卡内核驱动仍需按目标机显卡、内核预先安装。
存储建议安装前至少预留 70 GB（安装介质与解压副本同时保留时），另为新采集数据预留空间。使用 SSD 和 ext4 等 Linux 文件系统；拷贝大文件的移动盘使用 exFAT/ext4，勿用有 4 GB 单文件限制的 FAT32。
相机 / USB源机为两台 RealSense D405 和一台 ZED Mini，三路 RGB＋Depth。用可靠 USB 3 连接；插口标记 SS 不代表实际协商速度，使用 lsusb -t 核对。
机器人 / 夹爪源机 UR16e、OnRobot 2FG14、HEX-E QC。机器人需 Remote 模式并安装与现用 HEX 程序兼容的 OnRobot URCap。电脑包不安装控制器固件或 URCap。
网络源配置：UR 192.168.8.100，OnRobot 192.168.8.101，电脑 .200。更换电脑需避免重复 IP；无需公网。
界面 / 权限图形桌面、Chrome/Chromium，键盘输入焦点在操作台。提供浏览器副本、CJK 字体和可选 USB 权限脚本；串口需要 dialout 权限。

4. 离线安装与启动

  1. 把整个交付目录复制到目标机器，包括三个 tar.gz、脚本、tools、launchers、docs、inventory 和 udev；不要只复制某个压缩包。
  2. 目标机先准备 NVIDIA 驱动和 Ubuntu 图形桌面。安装脚本不运行 apt、不访问 pip、不修改源机。
  3. 执行以下命令。第二个路径是新采集数据的根目录，可改为已挂载 SSD 上的目录；安装目录必须不存在，以防覆盖旧版本。
cd /path/to/OHT_OFFLINE_PACKAGE
bash install.sh "$HOME/OHT_offline" "$HOME/OHT_data"
bash "$HOME/OHT_offline/check_environment.sh"
bash "$HOME/OHT_offline/start_oht.sh"

启动后访问 http://127.0.0.1:8779。模型管理服务为本机 8769；模型在点击加载后才占用 GPU，启动界面不会让机械臂运动。

若提示 USB/串口权限不足，在目标机明确执行下方命令，重新登录后再插入设备：

sudo bash "$HOME/OHT_offline/tools/install_usb_rules.sh" "$USER"

只开启相机：bash ~/OHT_offline/start_cameras.sh。它会启动相机，但不连接机器人。无需再开另一个 RealSense Viewer 争抢设备。

5. 首次使用与迁移配置

以 installation.json 中的 app、original、manager 为实际目录。源机硬件配置不是新机器的自动标定结果。

  1. 核对三路相机序列号。修改 app 和 original 下的 cameras.json，保留 camera_0 / camera_1 / camera_2 的映射。界面 CAM 01/02/03 分别对应上述三路，不能凭 USB 枚举顺序互换模型输入。
  2. 若仍用同一机器人，保持局域网地址；若更换机器人 IP/OnRobot 地址，需统一修改控制、只读路径检查和 HEX 通信配置，不只改网页。源配置 UR=.100、OnRobot=.101。
  3. 核对 GELLO 的 /dev/serial/by-id 路径、关节零偏及夹爪标定（teleop/calibrations）。现用 J6 安装补偿为 +90°，不能默认适用于另一台 GELLO。
  4. 源工具期望 TCP Z=232 mm、负载=2.5 kg、CoG=(-9, 6, 76) mm。只在实际工具一致时沿用；复制软件不会写入示教器 Installation。
  5. 夹爪目标范围为 5–55 mm，关闭端实测标定约 4.5 mm。对象被夹住时无需达到空载闭合宽度。
  6. 新机器不要复用旧路径检查缓存。相机外参和参考轮廓在 examples/source_machine 仅作为示例；安装位姿改变后重新标定/提取。

右上角语言选择支持 English / 中文 / 한국어，首次默认 English。语言切换不会改写历史数据或用户已输入的任务文本。

6. 手动完整任务采集

  1. 选择“手动 · 完整任务”，填写任务指令和最长时长。默认英文指令为 “Grasp the wheel and fit it onto the shaft.”。
  2. 先观察三路预览。设备检查可按需运行；“对齐 GELLO”是实际关节运动，要给机械臂和线缆留出完整通路。也可直接开启相对关节跟随，以双方当前姿态为基准，不做绝对对齐。
  3. 准备过程不算正式采集。确认状态后点击“开始采集”，才开始保存本条数据。相机保持常驻，下轮可复用。
  4. 可以切换键盘、GELLO、HEX 或手动轨迹辅助。轨迹辅助使用选择的参考并考虑当前进度和夹爪阶段；靠近插入位置前确认工件和参考一致。
  5. 成功或失败后结束本条，选择保留或删除。后台保存任务继续处理，界面允许的新一轮可继续；不要在“正在保存”时拔掉数据盘或关机。

夹爪可选择连续宽度跟随或捏合切换模式，界面独立开/关按钮同样可用。对齐后的夹爪宽度仍应实测确认。

平移按住连续移动、松开减速停止；当前名义线速度 40 mm/s，目标前导上限 4 mm。4 mm 是相对实测位置的前导额度，并不保证每按一次恰好移动 4 mm。

脚踏板绑定保存在浏览器本地，新电脑/新网页地址需重新绑定，可绑定键盘接管、GELLO 或轨迹辅助。自定义绑定优先，可能占用上述快捷键。输入框有焦点时先点击操作台空白处；F8 可能被系统占用，HEX 优先用数字 3。

界面 STOP 是结束电脑端采集流程的按钮。UR 控制器安全停止和硬件急停仍独立存在；不要把网页快捷键当作硬件急停。

8. DAgger 与 T42 Policy

加载其他 checkpoint：点击模型旁的“选择 checkpoint 文件夹”，浏览这台 OHT 电脑或已挂载的移动硬盘，也可直接输入路径。选择包含 COMMITTED.json、params/ 和 assets/ 的目录（通常为 20000），或选择其 params 子目录。界面自动识别模型配置，再点“选择并加载／预热”。登记会保留，刷新后不必重新登记。文件不会上传或复制，请保持原目录可访问。缺少训练配置、归一化或完整提交信息的任意权重目录不能直接加载。

  1. 选择 DAgger，模型选 T42 / 20,000。确认 GPU 0 或 GPU 1 实际存在且有空余显存；单卡机器使用 GPU 0。
  2. 选择普通 Policy 异步或 RTC，点击加载/预热，等待 READY。首次会编译，迁移后旧机器的编译缓存未沿用，可能比后续启动慢。
  3. 需要训练起点对齐时使用“对齐设备 · 训练轨迹起点”。这是实际运动；开环验证用的是已保存训练观测，不等同于闭环真实视觉反馈。
  4. 点击开始采集后运行 Policy。人工判断接近失败时按 1 键盘接管、按 2 GELLO、按 3 HEX，或选择轨迹辅助；按 7 交还 Policy。有效状态以界面提示为准。
  5. 全过程保留，并按控制来源分段。模型预测不自动等同于专家动作；后续训练可筛选人工纠正部分。

停止一轮不会卸载常驻模型；关闭浏览器也不等于退出模型进程。重启电脑后需重新加载。不要在采集中更换模型或强制杀进程。

接触保护只有正确的力输入、零点及运行状态下才有意义。界面的软件减速不是 UR 碰撞保护的替代品；配置含当前使用的控制参数，迁移后要重新核对工具和力信号。

9. 回放、过滤与轨迹扩充

  1. 在轨迹库选择成功轨迹。过滤会生成参考副本，原始图像/深度不改；过滤内容包括静止、小动作及过渡检查。速度倍率是名义参考时间，实际还会受跟踪、夹爪等待和控制限速影响。
  2. 切到轨迹多样性扩充，选参考并点击使用此参考，等待后台准备。完整回放入口已整合在此处，无需找旧 Replay 页面。
  3. 先对齐参考起点，再执行参考验证。对齐起点与中途找最近后续点是不同操作；后者需要保留任务进度及夹爪阶段，防止返回已完成的抓取/插入阶段。
  4. 参考验证后才进行自动扩充。时间变化改变节奏，空间变化改变实际经过的位置；结合偏移曲线观察各阶段及当前进度。
  5. 每条结束后确认结果、复位工件，再开始下一条。换参考会重新生成候选；不可将一次成功或旧缓存视为所有新路径已验证。

旧工装曾确认搬运等自由空间段可到 20 mm、接触前小偏移与接触后只改速度的范围。这是源现场条件，不是新机器默认安全距离。新安装需要重新核对相应阶段净空和接触位置。

10. 相机、图像增强与标定

  • 三路相机均保存 RGB 与深度；预览镜像、旋转、CLAHE、亮度/对比度只影响显示，不改原始训练图像。CAM 02 的旋转与相机输入角色也不要混淆。
  • 相机常驻进程只打开一次，正式采集时才落盘。USB 错误时先停止本轮，再恢复链路；不要同时启动多个相机所有者。
  • 相机校准：新建批次 → 采集 RGB 内参样本 → 求解内参 → 对所需相机求解外参 → 投影验证。已有一组外参即可验证对应相机，不必等三组全部完成。
  • 求解结果显示矩阵。需要时勾选将已求解内外参保存到采集数据；每条保存快照，避免后续重标定改写旧数据。
  • 参考轮廓：从成功轨迹自动寻找夹爪闭合前候选帧，确认轮子/夹爪区域，提取并保存。刷新后可复用已保存轮廓；更换相机姿态后重新生成。

更多旧版标定细节见随源码保留的中文校准说明。源机标定示例未自动启用，需确认相机角色、序列号、分辨率和实际安装姿态一致。

11. 结果保存与数据位置

默认安装命令的新数据在 ~/OHT_data/unified/episodes/<UTC编号>/；若指定其他路径，以 installation.json 和界面显示为准。

内容说明
annotation.json成功/失败、保留结果、备注和开头/结尾待删除标记；标记本身不裁剪图像。
metadata.json / collection_summary.json / quality.json任务、配置、完成状态和自动质量报告。操作员成功与质检通过是不同判断。
index.jsonl相机帧、UR 状态、夹爪/力数据和时间对齐索引；具体字段按 schema。
camera/三路 RGB、深度、时间戳与 SDK 标定。RealSense 深度比例见 calibration.json；ZED 深度为 uint16 毫米图。
teleop/机器人实际/目标、事件和结束诊断。HEX 六维数据与夹爪反馈按当前 schema 保存，不把 HEX 腕力当成夹指夹持力。
dagger_*/replay_*/augmentation_*控制来源、回放进度、扩充尝试及区段标签，按本轮模式生成。
camera_calibration/启用且可用时的内外参快照。

“删除数据”删除该条原始数据；“保留数据”保留并等待后台完成。自动质量报告异常需要查看具体缺帧/同步原因，不能仅因机器人完成动作就认定数据完整。

12. 常见问题与快速排查

现象处理
页面打不开 / 按钮灰色检查本机 8779/8769 和 ui_runtime/offline_server.log；处理上一条结果，核对当前阶段。不要为启用按钮而绕过服务状态。
相机可在别处打开，平台却报错关闭其他占用程序，核对 cameras.json 序列号、USB 3 协商速度和系统断连日志。浏览器刷新不能修复真实 USB 断线。
CAM01/02 无帧或碎条停止采集，用短线直连做单相机对照；避免不可靠延长线和共享 USB 2 带宽。必要时检查独立控制器/供电。
ZED import / libturbojpeg / libsl_zed 错误先用 check_environment.sh 确认 bundled 库已生效，始终通过包内启动脚本启动；再核对 NVIDIA 驱动和 SDK。
Policy 无法加载核对 T42 单模型登记、20,000 步元数据和完整权重；GPU显存、tokenizer缓存、runtime 是否齐全。勿自动联网下载替代模型。
键盘无响应先切换到键盘控制、点操作台空白处，核对锁止提示与脚踏板优先绑定。5/6 是直接开闭；移动键需按住。
采集目录未就绪核对 installation.json 中的数据路径与磁盘挂载；不要把坏链接改到系统盘来隐藏错误。
保护停止 / TCP或负载不匹配在示教器查看具体故障；核对实际工具、工件、力和路由。不要关闭 UR 自身安全限制来通过检查。

lsusb -t

13. 备份、升级与验证边界

  • 保留交付目录及 SHA256SUMS。安装器拒绝覆盖已存在目录；升级使用新目录，旧版作为可回退副本。
  • 正式采集结束并完成结果选择后再更新代码；先备份配置、参考轨迹、标定和数据。不要带入旧 PID、运行锁、认证令牌或路径验证缓存。
  • 数据独立存储，备份数据时保留 index、metadata、annotation、力/机器人日志和 camera 全部内容，不能只拷视频。
  • 此包验证的是文件完整性、路径迁移、依赖导入和离线页面。未在目标机器进行相机实采、GPU模型预热或 UR 真机运动验证；环境报告中失败项应先解决。
  • 源码和模型配置保留，第三方组件许可证随原目录保留；厂商 SDK/驱动按其许可使用。

交付版本、包含项和排除项见 package.json；实际打包验证见 verification.json。
